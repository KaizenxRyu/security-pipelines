# Contributing

Add a focused pipeline with a clear scope, synthetic examples, measurable expectations and readable evidence. Include both forbidden behavior and legitimate requests, plus malformed-input and recovery checks. Keep checks modular and document what they cannot establish.

Run `python -m unittest discover -s tests -v` and the affected pipeline before submitting. Update intent, status, architecture, sources and findings for behavior changes. Do not place credentials, customer data, proprietary code or raw private model outputs in Git. Provider calls need separately authorized spending and data access.

Public issues may describe a limitation without revealing customer material. Report a suspected vulnerability privately to rahulchamoli.in+security@gmail.com before including exploit details publicly.
